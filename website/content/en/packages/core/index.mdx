`@pera1/core` is the router core of pera1. It handles normalization and matching of route definitions, execution of loaders and actions, per-history-entry data management, and integration with engines. It does not depend on React, so bindings for other UI frameworks and fake engines for testing can use it the same way.

## Installation [#install]

```package-install
npm i @pera1/core valibot
```

`valibot` is a peer dependency used for runtime validation. When you use `@pera1/react`, the core is installed automatically.

## Entry points [#entry-points]

The package has 3 entry points. In most cases the root `@pera1/core` is all you need.

| Import | Contents |
| --- | --- |
| `@pera1/core` | Router, matching, loaders, actions, engines, errors, types |
| `@pera1/core/core` | Core routing APIs (`createRouter`, `matchRoutes`, and more) |
| `@pera1/core/engines` | Engine interfaces and `NavigationApiEngine` |

## Design principles [#principles]

- **Synchronous `init`**: Engine initialization is synchronous. Information needed for the initial render is returned immediately, while async data fetching is wrapped in `NinjaPromise` and registered in the store.
- **Stable references**: Router snapshots have stable references; only `currentEntry` changes. Subscribers pick out what they need with selectors.
- **Per-history-entry cache**: Data is kept per history entry ID, and data for discarded entries is removed automatically.
- **Failures as data**: Exceptions from loaders and actions are kept as `rejected` `NinjaPromise` values; presentation decisions are left to the UI.
