title: プラグインのオプション
description: "pera1() のオプションと、仮想モジュールが提供する API をまとめます。"
---

`@pera1/vite` の既定エクスポートは `pera1()` です。Vite の `plugins` に追加すると、ページディレクトリーの走査、仮想モジュール `virtual:pera1/routes` の提供、ルート型の生成を行います。

```ts
import pera1 from "@pera1/vite";
```

## シグネチャ [#signature]

```ts
function pera1(options?: Pera1VitePluginOptions): Plugin;
```

## オプション [#options]

| オプション | 型                  | 既定                                             | 説明                                                                                           |
| ---------- | ------------------- | ------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| `dir`      | `string`            | `"src/pages"`                                    | ページディレクトリーの、プロジェクトルートからの相対パスです。                                 |
| `include`  | `readonly string[]` | `["**/*.tsx", "**/*.ts", "**/*.jsx", "**/*.js"]` | ルートとして扱うファイルの glob パターンです。ページディレクトリーからの相対パスで指定します。 |
| `exclude`  | `readonly string[]` | `[]`                                             | ルートから除外するファイルの glob パターンです。`include` より優先されます。                   |
| `typesDir` | `string`            | `".pera1/types"`                                 | ルート型の生成先の、プロジェクトルートからの相対パスです。                                     |

```ts vite.config.ts
import pera1 from "@pera1/vite";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [
    pera1({
      dir: "app/routes",
      include: ["**/*.tsx"],
      exclude: ["**/*.test.tsx", "_components"],
    }),
  ],
});
```

`include` と `exclude` の評価には Node.js 組み込みの `fs.globSync` を使います。パターンはページディレクトリーからの相対パスで、`exclude` に一致するものは `include` に一致していても対象外になります。ディレクトリー名だけを指定すると、その配下がまとめて除外されます。

:::note
`exclude` の glob パターンを使うため、Node.js 22.17 以上が必要です。
:::

## 仮想モジュール [#virtual-module]

プラグインは `virtual:pera1/routes` を解決し、ルート定義をエクスポートします。仮想モジュール ID は `VIRTUAL_ROUTES_ID` としても公開しています。

```tsx
import { routes } from "virtual:pera1/routes";
```

| エクスポート | 型                                        | 説明                                           |
| ------------ | ----------------------------------------- | ---------------------------------------------- |
| `routes`     | `readonly RouteDefinition<string, any>[]` | ファイル構成から生成したルート定義の配列です。 |
| default      | 同上                                      | `routes` と同じ配列です。                      |

型定義は `@pera1/vite/client` に含まれています。`tsconfig.json` の `types` へ追加するか、ソースの先頭で参照してください。

```json tsconfig.json
{
  "compilerOptions": {
    "types": ["vite/client", "@pera1/vite/client"]
  }
}
```

生成したルート定義は、そのまま `BrowserRouter` や `createRouter` に渡せます。詳しいファイルの対応規則は[ファイルの規約](/packages/vite/reference/file-conventions)を参照してください。

## 開発サーバーでの動き [#dev-server]

- サーバーの起動時にルート型を生成します。
- ページディレクトリーのファイル追加・変更・削除を監視し、ルート型を再生成します。
- ファイルの追加と削除では、仮想モジュールを無効化してページ全体を再読み込みします。内容の変更は Vite の HMR に任せます。
- ルート型の生成に失敗しても、開発サーバーは警告を出すだけで停止しません。

## ビルドでの動き [#build]

- `vite build` の開始時にルート型を生成します。
- `vite build --watch` では、ページディレクトリーの変更を検知して再生成します。
- 仮想モジュールの生成に使うページモジュールは、ウォッチ対象として登録されます。
