---
title: selectActionData と selectLoaderData と selectNavigationState
description: "スナップショットからデータと遷移状態を選び出すセレクターです。"
---

`selectActionData` と `selectLoaderData` はルーターのスナップショットからデータを取得する純粋なセレクター関数です。React バインディングの `useActionData` と `useLoaderData` は内部でこれらを呼んでいます。`selectNavigationState` は現在の履歴エントリーに紐づく遷移状態を導出するセレクターで、`useNavigation` の土台になっています。いずれもフレームワークには依存しません。そのため、Solid.js 向けのバインディングやテストからも同じロジックを共有できます。

```ts
import { selectActionData, selectLoaderData, selectNavigationState } from "@pera1/core";
```

## シグネチャ [#signature]

```ts
function selectActionData(
  snapshot: Pick<RouterSnapshot, "currentEntry" | "actionDataStore">,
  action: ActionFunction | undefined,
): NinjaPromise<unknown> | undefined;

function selectLoaderData(
  snapshot: Pick<RouterSnapshot, "currentEntry" | "loaderDataStore">,
  loader: LoaderFunction | undefined,
): NinjaPromise<unknown> | undefined;

function selectNavigationState(
  snapshot: Pick<RouterSnapshot, "currentEntry" | "actionDataStore" | "loaderDataStore">,
): NavigationState;

type NavigationState = "idle" | "loading" | "submitting";
```

## 引数 [#arguments]

| プロパティー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `snapshot` | `Pick<RouterSnapshot, ...>` | はい | `createRouter` が返すコントローラーの `getSnapshot()` の結果です。 |
| `action` / `loader` | `ActionFunction \| undefined`、`LoaderFunction \| undefined` | はい | 取得したい対象の関数です。`undefined` を渡すと `undefined` を返します。 |

第 1 引数は `RouterSnapshot` 全体ではなく、必要なプロパティーだけを取り出した `Pick` 型です。そのため、テストでは最小限のオブジェクトをそのまま渡せます。

## 戻り値 [#returns]

| 条件 | 戻り値 |
| --- | --- |
| 関数が `undefined` | `undefined` |
| 現在の履歴エントリーに対応するデータがない | `undefined` |
| 実行済みまたは実行中 | `NinjaPromise<unknown>` |

`NinjaPromise` は解決済みとは限りません。thenable なので、UI 側では `React.use` に渡し、未解決なら `Suspense`、拒否ならエラーバウンダリーに任せるのが基本です。まだ一度も実行されていない場合だけ `undefined` になります。

```ts no-run
import { selectLoaderData } from "@pera1/core";

const snapshot = controller.getSnapshot();
const data = selectLoaderData(snapshot, loader);

if (data) {
  // thenable として UI 層の非同期プリミティブに渡す
  // React なら React.use(data) が Suspense とエラーバウンダリーにつなぐ
}
```

## 注意 [#notes]

- どちらの関数も状態を変更しません。新しい値を作らず、ストアから既存の `NinjaPromise` を返すだけです。
- データは履歴エントリー ID ごとに保持されます。照合に使われるのは `snapshot.currentEntry.id` だけです。
- `action` や `loader` が関数でない場合は、ストアを参照せずに `undefined` を返します。

## 遷移状態の選択 [#navigation-state]

`selectNavigationState` は、現在の履歴エントリーに紐づくアクションとローダーの `NinjaPromise` の状態から、遷移状態を導出します。

| 状態 | 条件 |
| --- | --- |
| `"submitting"` | 現在のエントリーのアクションに `pending` がある |
| `"loading"` | アクションの `pending` はなく、ローダーに `pending` がある |
| `"idle"` | どちらにも `pending` がない、またはスナップショットが未初期化 |

アクション (`"submitting"`) の判定がローダー (`"loading"`) より優先されます。スナップショットが未初期化の場合も `"idle"` を返します。

```ts no-run
import { selectNavigationState } from "@pera1/core";

const snapshot = controller.getSnapshot();
const state = selectNavigationState(snapshot);

if (state !== "idle") {
  // 遷移全体の進行中表示を出す
}
```
